# Change: Chunk Interest Aggregator (chunkd-side event hub)

## Why
Bonfированы две проблемы, обе из одного корня: **топология сервисов строится из событий
взаимодействия** (`world.blocks.changed` от клика/установки), а не из факта загрузки чанка.
- При загрузке мира/чанка подписчики (simcore, pipenetworkd) **не получают информации о
  содержимом чанка**, поэтому машины и трубы в холодном чанке не регистрируются, пока их
  не "пинком" (кликом/рейкстом) не заденет клиент. Признак: "пар доходит только до 2-й
  трубы", "вверх — пусто", снос+перестановка "чинит".
- Прямая реакция на `world.chunk.loaded.compressed` **захлебнётся**: chunkd шлёт полный
  сжатый чанк, а распарсить его и отфильтровать нужные блоки — дорого, плюс N сервисов
  подписались бы каждый на всё.

## What Changes
- **Новый сервис `chunk_interest`** (C++): владеет **статусом загруженности чанков**
  (loaded / unloaded), который **переносится из simcore**. chunkd остаётся кэшем/хранилищем
  блоков, не владельцем статуса "обработан ли чанк логикой".
- Сервисы (**simcore**, **pipenetworkd**, будущее spatial_index) **регистрируют диапазоны
  item-id**, которые им нужны (`registerRange(client, {pipe: 33..60}, chunkXZ..., ...)`).
- Сервис подписан на:
  1. `world.chunk.loaded.compressed` (от chunkd) — факт загрузки чанка с дельтами блоков.
  2. `world.blocks.changed` (клик/установка через simcore) — точечные изменения; simcore
     дублирует в агрегатор то, что шлёт в chunkd (один sender — chunkd, агрегатор фэнаутит).
- Сервис **агрегирует по времени (debounce/batch)**: копит находки и рассылает пачкой, а не
  событием на каждый блок.
- Если в (повторно) загруженном чанке найден нужный id — сервис нотифицирует подписчиков.
- При **выгрузке чанка** (`chunk.unloaded`) — нотифицирует подписчиков с границами чанка,
  чтобы те сносили локальные сущности/рёбра ("вот границы — выгрузи их").

## Impact
- Affected specs: `pipes-cables-transport`, `player-interaction`, `protocol`, новая
  `chunk-interest-aggregator`.
- Affected code: новый `src/services/chunk_interest/`, `simulation_core` (отдать владение
  статусом чанков), `pipe_network` (подписка на батч-нотификации + снос рёбер при unload),
  `protocol/*.fbs` (new messages: interest-register/unregister, chart- notify batch),
  `chunk_store` (unloaded already published — проверить формат).
- **BREAKING**: статус загруженности чанка переносится из simcore в новый сервис.

## Non-Goals
- Не реализация spatial_index (R-tree/Octree). Этот сервис — фильтр-дистрибьютор интересов,
  не пространственный индекс.
- Не решение бага "до 2-й трубы" при живом клиенте — тот чинится отдельно точечным фиксом
  рёбер труба↔труба в `handleBlockChanged` (см. баг-фикс, вне этого пропозала).

## Status
**DEFERRED** — зафиксирован дизайн, реализация отложена. Сначала чинится баг рёбер
труба↔труба (точечный фикс), затем этот пропозал под реконсиляцию топологии из мира.
