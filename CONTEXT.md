# GTNH Platform

Распределённая платформа в стиле Minecraft: C++ ядро производительности (симуляция, хранение, транспорт) + Go-сервисы обвязки, соединённые бинарным протоколом через MessageRouter. Клиент — тонкий терминал: он не владеет авторитетным состоянием и не знает бизнес-семантику мира.

## Language

### Мир и блоки

**Блок (Block)**:
Единица мира с id и meta. Клиент кликает по блоку как таковому — что это (машина, сундук, труба), решает сервер.
_Avoid_: «машина» применительно к тому, что видит клиент

**BlockRegistry**:
Доменная библиотека, единственный источник идентичности блоков домена: таблица id↔(тип, тир) и раскладка face-битов meta, парсится в рантайме из `data/registry/*.csv`. Линкуется только сервисами, которым этот домен нужен.
_Avoid_: ручные копии таблиц, общая «либа всего»

### Транспорт жидкостей и энергии
Термины раздела описывают целевую модель учёта (ADR-0003). В текущем коде транзакции называются FluidRequest/FluidConsumeResponse, а drain сети от источников идёт через drainFluidFromNetwork.

**Транзитный буфер (TransitBuffer)**:
Содержимое труб (пар, тепло, жидкости), принадлежащее pipe_network. Единственная копия этих чисел живёт там.
_Avoid_: зеркальные копии буферов на simcore

**Пул машины (MachinePool)**:
Внутренние запасы машины (пар котла, энергия), принадлежащие simcore. Списать из пула может только транзакция, инициированная сетью; владельцу принадлежит guard: он сам режет отдаваемое количество.
_Avoid_: синхронизация копий пула

**DrainRequest / Accepted**:
Запрос сети источнику «отдай N», ответ владельца «принято M ≤ min(N, пул)». Обе стороны транспорта — request/response; ответ и есть оповещение в обратку.
_Avoid_: однонаправленные события состояния, seq/ресинк-базлайны

**Подпитка (Top-up)**:
Периодическое батчевое заполнение труб из источников по свободному месту без конкретного потребителя. Так же сете-инициирована, рейт-лимитится. Подпитка ничего не знает о потребителях: пока не произошёл consumer drain, трубы просто стоят полными — «трубы забиты, а машина не получает» значит, что потребитель не опубликован, а не что подпитка сломана.
_Avoid_: per-tick заливка

**Пробник (Check)**:
Read-only запрос «сколько есть» — ничего не дебетит.
_Avoid_: использование check как списания

**Replay-дедупликация**:
Защита ретраев на мутирующих запросах: получатель по request_id возвращает точный байтовый повтор прошлого ответа (не факт «видел id»). Гарантирует однократное применение действия.
_Avoid_: дедуп «consumed=0» на повтор, query-of-intent протоколы

**Регистрация (Registration)**:
Сообщение топологии при постановке/ломании блока и при редких изменениях, влияющих на граф (перенастройка граней ключом, смена тира). Не поток состояния.

**Протухший источник (Stale Source)**:
Источник без регистраций и транзакций дольше K секунд — исключается из роутинга спроса, его трубы дренируются. Заменяет собой heartbeat убитого per-tick потока.

### Клиент

**MachineStateStore**:
Клиентский типизированный стор: декодирует сетевые сообщения один раз, держит состояние по позиции; окна машин читают готовое состояние и не знают протокол. Staleness-политика — деталь реализации стора.
_Avoid_: парсинг FlatBuffers в каждом окне
