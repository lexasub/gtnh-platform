# Идентичность блоков — доменные реестры, парсинг в рантайме
Status: Proposed — библиотека block_registry не реализована; pipe_network и game_client пока продолжают держать дубли таблиц. Решение принято, код не написан.

Таблицы id↔тип/тир и раскладка face-битов для труб/кабелей были скопированы руками в ~8 местах между game_client и pipe_network — этот класс дублей уже дал продакшн-десинк (постмортем 2026-08-11). Решение: единственный источник — `data/registry/*.csv`; доменная библиотека (`src/libs/block_registry/` для труб/кабелей) парсит их в рантайме и отдаёт типизированные таблицы. Линки строго по домену: сервис линкует только те реестры, которые реально читает (block_registry — pipe_network, game_client, simulation_core; MessageRouter/meta_db/ChunkStore — никогда). Текстурные мапинги остаются клиентскими и строятся поверх данных реестра. Go-сервисы эти таблицы не потребляют (проверено) — Go-стороны у реестра нет.

## Considered Options

- Одна большая «либа всего» на все реестры — отклонено: сервер не должен линковаться с библиотекой текстурных мапингов; режем по доменам (прецедент: machine_registry).
- Билд-кодогенерация C++/Go констант из CSV — отложено: без нового шага сборки дрейф невозможен и так (один парсер); генерацию можно добавить позже при росте числа потребителей.
- Ручные копии + контрактные тесты (как WrenchMetaLink_test) — отклонено как целевое состояние: тест детектирует дрейф, либа его исключает.

## Consequences

- Добавление типа трубы/кабеля = правка CSV, а не 8 файлов.
- Первый заход: pipes.csv + cables.csv; интерфейс закладывается под остальные реестры реестра (machines.yaml, fluids.csv, …) по мере касания.
