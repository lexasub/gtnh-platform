# Учёт пара/жидкостей: request/response в обоих направлениях, один владелец на число (модель A′)

Инвариант сохранения пара сегодня размазан по проводy: pipe_network дебетирует свои узлы и публикует `fluid.flow`, simcore зеркально переприменяет дебет через FluidFlowHandler — любая потеря шага тихо портит пар. Решение: каждое число имеет ровно одного владельца (транзитные буферы труб — pipe_network, пулы машин — simcore), любое пересечение границы «сеть ↔ машина» — транзакция request/response: сеть инициирует `drain.request N` → владелец отвечает `accepted M ≤ min(N, пул)` (guard пула у владельца); потребителю дельта едет в consume-response. Check остаётся read-only пробой. Per-tick broadcast состояния узлов умирает; остаются регистрации топологии (+ редкие события: перенастройка граней, тир), а живость источников обеспечивается stale-timeout (~5 c), не heartbeat'ом. Оба режима drain сохраняются: реактивный под потребителя и батчевая рейт-лимитимая подпитка труб. Ретраи на мутирующих запросах защищены replay-дедупликацией (кэш байтов ответа по request_id, LRU ~256 + возрастной кап); pending-таймауты и бэкофф после нулевого short-fill обязательны независимо от модели — завис pending существует уже сегодня. Seq/snapshot-ресинки не нужны вовсе: реконнект = перерегистрация.

## Considered Options

- Дельты + seq + ресинк через check (snapshot-and-delta-log) — отклонено: check агрегирован по сети (нет per-source разбивки), снапшот надо координировать с seq — мини-протокол репликации сложнее самого учёта.
- События + ack поверх двойной записи — отклонено: тот же размазанный инвариант, только с детектором собственных багов.
- Перенос пулов машин в pipe_network — отклонено: ломает владение ECS со стороны simcore.
- Инициатива push от источника — отклонена: сеть единственная знает спрос; источник остаётся «спросили — отдал».

## Consequences

- FluidFlowHandler удаляется целиком; simcore становится тупым апплаером ответов.
- Цепочка на промахе удлиняется на один RTT (consume → трубы пусты → drain → resp → consume.resp); на 20 Hz приемлемо, но старт макератора замерить тестом.
- Реализация отложена до окончания текущей работы другого агента над паром в трубах.
