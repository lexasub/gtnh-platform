# Клиент не владеет авторитетным состоянием и бизнес-семантикой

Клиент — терминал: он кликает по блоку как таковому и получает от сервера команды (например, «открыть окно»); он не знает, машина перед ним или сундук, не держит авторитетных копий состояния и всегда запрашивает свежие данные у сервера. Мотивация — консистентность, а не безопасность: сервер может менять мир в любой момент, любая локальная «знайка»-копия расходится. Допустимое исключение — детерминированный вывод формы для рендера: клиент строит меш из блоков/meta чанков; раскладка битов meta — общий wire-контракт (см. ADR-0002), а не серверное состояние.

## Consequences

- Новые окна/оверлеи читают состояние через MachineStateStore (декод сети один раз), а не парсят протокол самостоятельно.
- Фичи вида «выбор награды в квестбуке» обязаны ехать по проводу: интерфейс не должен обещать больше, чем реализует сервер (урок с декоративным choice-of-rewards).
- Staleness/heartbeat-эвристики клиента — эвристики отображения, не источник истины.
